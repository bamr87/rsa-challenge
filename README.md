# rsa-challenge

Generate RSA factoring / decryption challenges at any size and self-check solutions in the browser —
a small homage to the [RSA Factoring Challenge](https://en.wikipedia.org/wiki/RSA_Factoring_Challenge)
(RSA-100 style ids name decimal digits; `RSA-<bits>b` ids name bit length, like RSA-576).

**Site:** https://bamr87.github.io/rsa-challenge/ · **Data:** [`challenges/challenges.json`](challenges/challenges.json)

## How a challenge works

For each challenge the generator picks two random primes `p < q` (Miller–Rabin, Python `secrets` RNG),
publishes `N = p·q`, `e = 65537`, and the ciphertext `c = m^e mod N` of a random secret message.

- **Encryption is textbook RSA** (no padding / no OAEP): `m` is the message's UTF-8 bytes read as a big-endian integer.
  That is insecure by design and only appropriate for a puzzle.
- **Commitments:** `factors_sha256 = SHA-256("<p>,<q>")` (decimal, smaller first) and `plaintext_sha256 = SHA-256(message)`.
- Solve by submitting **p and q**, the **private exponent d** (checked by decrypting `c`), or the **plaintext**.

Public file fields: `id, bits, digits, n, e, c, factors_sha256, plaintext_sha256, encryption, created`. Nothing else.

## Seeded challenges

| id | bits | digits | difficulty |
| --- | --- | --- | --- |
| RSA-32b, RSA-48b, RSA-64b | 32–64 | 10–20 | instant (trial division / Pollard rho) |
| RSA-128b, RSA-40 | 128–131 | 39–40 | seconds–minutes with ECM/QS (e.g. `yafu`, `msieve`) |
| RSA-256b | 256 | 77 | hours with a decent QS/NFS setup |
| RSA-100 | 330 | 100 | same size as the original RSA-100 (factored 1991); a day or so with CADO-NFS |
| RSA-512b | 512 | 154 | RSA-155-sized; serious NFS compute |
| RSA-768b, RSA-1024b, RSA-2048b | 768–2048 | 232–617 | infeasible / research-grade |

## CLI (Python ≥ 3.9, stdlib only)

```bash
pip install -e .            # or: python3 -m rsa_challenge ...
rsa-challenge generate --bits 64 256          # RSA-64b, RSA-256b
rsa-challenge generate --digits 100           # RSA-100 (exactly 100 decimal digits)
rsa-challenge generate --default-set          # 64 128 256 330 512 768 1024 2048 bits
rsa-challenge generate --bits 96 --id my-96   # custom id
rsa-challenge generate --bits 64 --dry-run    # print public JSON only
rsa-challenge list
rsa-challenge verify RSA-64b --p 123 --q 456  # or --d ... / --plaintext ...
rsa-challenge solve-small RSA-64b             # Pollard rho demo, ≤ 100 bits
```

Public data is appended to `challenges/challenges.json`; private data (`p, q, d, plaintext, m`) goes to
`secrets/<id>.json` (gitignored, mode 600) or `--secrets DIR`. **Never commit secrets.**
`python3 scripts/check_no_secrets.py` (run in CI and before every Pages deploy) fails if anything under
`secrets/` is tracked, if `challenges.json` carries a non-public key, or if any local secret value appears
in a tracked file.

## Frontend

`site/` is plain HTML + JS (no build). `site/verify.js` uses `BigInt` and Web Crypto SHA-256 to check
`p·q == N`, both `> 1`, the factor hash, `c^d mod N` → plaintext hash, or the plaintext hash.
**Verification is client-side self-check only — there is no server and no leaderboard.**
Deployed by `.github/workflows/pages.yml` (GitHub Pages, build from Actions).
