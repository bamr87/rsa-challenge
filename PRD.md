# PRD — rsa-challenge

## 1. Purpose

Give puzzle-solvers and people learning RSA a set of factoring / decryption challenges at graded sizes,
modelled on the RSA Factoring Challenge, plus a zero-install way to check a solution.

## 2. Users

- Solvers who want to test factoring tools (Pollard rho, ECM, QS, NFS) against known-hard sizes.
- The maintainer, who generates and publishes new challenges.

## 3. Requirements

**Functional**

- FR1: The CLI generates RSA challenges by bit length (`--bits`) or decimal digits (`--digits`), with e = 65537.
- FR2: Each challenge publishes N, e, a textbook-RSA ciphertext c of a random secret plaintext, and SHA-256 commitments of the sorted factors and of the plaintext.
- FR3: Private material (p, q, d, plaintext) is written only to a gitignored secrets directory.
- FR4: A `verify` CLI checks a submission of factors, private exponent d, or plaintext.
- FR5: A static web page lists published challenges and verifies submissions client-side (factors, d, or plaintext) with clear success/failure.
- FR6: The repo ships a seeded set of challenges from trivially solvable to infeasible sizes.

**Non-functional**

- NFR1: Secret material must never be committed; an automated check enforces this in tests, CI and before deploy.
- NFR2: The generator uses only the Python standard library and a CSPRNG (`secrets`).
- NFR3: The frontend needs no build step and is deployed via GitHub Pages from Actions.
- NFR4: The site states that verification is a client-side self-check, not a leaderboard.

## 4. Out of scope

Server-side submission, leaderboards, prizes, padded (OAEP) encryption.
